Avant de lancer le script

Ton ordinateur est-il prêt pour Hermes ?

Le kit accompagne la méthode en terminal. Vérifie ces points, puis lis le GUIDE.md avant toute exécution.

  • macOS Apple Silicon : la méthode officielle en terminal est prise en charge. Pour un Mac Intel, lis la réserve ci-dessous avant de lancer le kit.
  • Linux ou WSL2 : architectures x86_64 ou arm64 (aarch64). La documentation indique des tests sur Ubuntu récent et WSL2 ; cela ne garantit pas chaque distribution.
  • Outils requis : Git, curl, tar et un utilitaire SHA-256. L’installateur fournit son environnement Python et Node.js ; la compilation peut aussi demander un compilateur et des bibliothèques système. Sur Linux, certains composants nécessitent des paquets système et les droits d’un administrateur.
  • Windows natif : le script Bash du kit ne se lance pas directement dans PowerShell. Utilise le kit dans WSL2, ou suis la méthode officielle Windows hors de ce kit.
Mac Intel : compatibilité non garantie

Au contrôle du 16/10/2026, les pages officielles divergent : le guide d’installation présente macOS Intel comme non pris en charge, tandis que la matrice des plateformes décrit encore une installation CLI et des bundles Intel disponibles seulement sur certaines releases.

Les prérequis du guide et du README, consultables en ligne et dans le ZIP, reprennent cette réserve. Le message du script sur Intel ne constitue pas une garantie. Vérifie ces deux sources pour ta machine et ta version avant de lancer un installateur ; en cas de doute, demande confirmation au projet Hermes.

Avant de confier tes données

Confidentialité : garde la main sur le périmètre

Le kit reste gratuit. Avant un premier essai, choisis des fichiers publics ou fictifs, une tâche courte et les seuls accès nécessaires. Voici cinq repères, pas une politique juridique.

1. Un fournisseur distant : qu’est-ce que je lui envoie ?

Le fournisseur distant reçoit le contexte envoyé au modèle : tes messages, mais aussi les extraits de fichiers ou résultats d’outils ajoutés à la conversation. Cela ne signifie pas que tout ton disque lui est envoyé. Limite les données confiées et vérifie les conditions du fournisseur, notamment leur conservation et leur utilisation.

2. Un modèle local veut-il dire « hors ligne » ?

Un modèle local peut calculer sur ta machine, mais les outils connectés, comme la recherche web, le navigateur ou une API, peuvent encore communiquer avec des services externes. Vérifie aussi les services annexes que tu actives : choisir le modèle ne suffit pas à garantir un usage hors ligne.

Le guide du kit détaille ces précautions, y compris les modèles auxiliaires et les fournisseurs de secours : vérifie aussi leur destination.

3. Quels accès donner pour un premier essai ?

Commence avec des droits minimums et un dossier dédié contenant seulement des copies non sensibles. N’accorde pas de droits administrateur ni d’accès à tes comptes sans besoin précis. Lis les demandes d’autorisation au lieu de tout approuver.

Un dossier de travail est un point de départ, pas une barrière d’accès à lui seul : le terminal local agit avec les droits de ton utilisateur. Pour isoler réellement l’exécution, consulte les limites et options d’isolation de la documentation officielle.

4. Que garder privé après une session ?

L’historique, les journaux et les sauvegardes peuvent contenir des informations sensibles ; une sauvegarde peut aussi inclure des secrets. Garde-les dans un emplacement à accès restreint, pas dans un dossier public ou partagé sans contrôle.

Ne diffuse pas tes clés API, mots de passe, jetons, fichier .env ou sauvegarde complète. Un historique conservé sur ta machine ne prouve pas que son contenu n’a jamais été transmis au modèle.

5. Comment demander de l’aide sans tout partager ?

Avant de transmettre un diagnostic, vérifie sa destination : certaines fonctions de partage envoient les journaux à un service externe. Prépare un extrait minimal de l’erreur, puis relis le texte et les captures pour retirer secrets, données personnelles et documents confidentiels.

Le masquage automatique ne remplace pas cette relecture. Si tu ne sais pas ce qu’un rapport contient ou à qui il sera envoyé, ne le partage pas encore.

Installation bloquée ? Commence ici

Trois vérifications après une installation en terminal sur macOS ou Linux. Exécute les commandes dans ton terminal personnel, pas dans une conversation avec l’agent.

Le terminal affiche « hermes: command not found »

Ouvre un nouveau terminal, puis réessaie hermes. Tu peux aussi recharger la configuration du shell que tu utilises : source ~/.zshrc pour zsh, ou source ~/.bashrc pour bash.

Si la commande reste introuvable, vérifie que le dossier ~/.local/bin du lanceur figure dans ton PATH. La documentation officielle détaille ce contrôle : une commande introuvable ne signifie pas forcément que tu dois tout réinstaller.

Hermes démarre, mais le modèle ou la clé API manque

Lance hermes model pour choisir ou reconfigurer ton fournisseur et ton modèle. Si tu utilises une API en ligne, vérifie aussi la validité de ta clé et les limites de ton compte chez ce fournisseur. Pour un modèle local, vérifie que son serveur est démarré.

Garde la clé dans la configuration privée de Hermes : ne la colle ni dans les fichiers publics du kit ni dans une demande d’aide.

Un autre blocage, ou une installation incomplète ?

Lance hermes doctor pour obtenir un diagnostic, puis consulte logs/install.log dans le dossier de données Hermes si l’installation a échoué. Le dossier habituel est ~/.hermes. Ne supprime pas ce dossier pour tenter de réparer : il contient aussi ta configuration et tes données.
